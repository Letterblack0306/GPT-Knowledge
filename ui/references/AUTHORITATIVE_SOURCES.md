# Authoritative UI Design Sources

Use these sources for research and verification. They are references, not templates to copy blindly.

## Microsoft Fluent 2

Use for:

- platform familiarity
- focus and reduced visual noise
- inclusive design
- design tokens
- command patterns
- content design

Key extracted principles:

- adapt to the platform
- use native patterns where practical
- keep users in flow
- reduce clutter
- design for a range of abilities
- use plain, direct interface language

## Windows App Design Guidance

Use for:

- desktop conventions
- commanding
- layout
- typography
- color
- motion
- materials
- Windows-specific interaction expectations

## Apple Human Interface Guidelines

Use for:

- hierarchy
- consistency
- platform conventions
- adaptive layout
- components and input patterns
- accessibility

Extract universal behavior, but do not copy Apple-specific visual conventions into unrelated platforms.

## Material Design 3

Use for:

- canonical layouts
- responsive breakpoints
- list–detail patterns
- supporting panes
- layout scaffolds
- adaptive navigation

## W3C ARIA Authoring Practices Guide

Use for:

- semantic widgets
- roles, states, and properties
- keyboard interaction
- accessible tabs, trees, menus, dialogs, grids, and other patterns

Important boundary: APG is accessibility implementation guidance, not a complete visual design system.

## Additional systems to research

- GitHub Primer — dense developer workflows, tables, diffs, navigation, status
- IBM Carbon — enterprise forms, data tables, notifications, progressive disclosure
- Atlassian Design System — task-oriented product workflows, content design, filtering
- Shopify Polaris — configuration, setup, validation, empty states

## Source handling rule

Each knowledge entry should distinguish:

```text
Source statement
Extracted universal principle
Project-specific interpretation
Runtime-validated lesson
```

Do not present interpretations as direct source requirements.

## Review cadence

- verify links and guidance when a document is materially updated
- record `last_reviewed`
- mark outdated guidance as superseded instead of silently deleting history
- prefer primary design-system and standards documentation over articles or screenshots
