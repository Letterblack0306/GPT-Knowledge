## Scope and safety

- This is an access snapshot, not a permanent inventory.
- Repository visibility and default branches can change.
- A listed repository is not automatically relevant to every task.
- Always inspect the target repository, active branch, README, status, and current contracts before making changes.
- Never infer project purpose, architecture, health, or implementation status from the repository name alone.
- Private source content, secrets, machine paths, tokens, internal endpoints, and unpublished design details are intentionally excluded.

## Required repository-use procedure

Before using any repository as context or applying a change:

```text
1. Confirm connector access still exists.
2. Read repository metadata and default branch.
3. Inspect README and repository-local instructions.
4. Inspect branches, current issue/PR, and active work scope.
5. Read the exact target files before proposing changes.
6. Separate facts from name-based inference.
7. Create or use a scoped branch.
8. Validate changed files and repository-defined checks.
9. Report exact evidence and bound claims to what was verified.
```

## Registry maintenance

Update this file when:

- repository access changes;
- a repository is added, renamed, transferred, archived, or deleted;
- visibility or default branch changes;
- a repository’s purpose has been verified from its own documentation;
- the GitHub connector installation changes.

Do not silently remove historical entries. Record removals or access loss in a dated registry change log when this repository becomes private and deeper inventory tracking is appropriate.
